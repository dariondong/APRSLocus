📡 Saturday check-in

APRSNETCN OA · #261024 Half a Cat BedEvery Saturday, on air

A whole Saturday, Beijing time. Address the message to the duty callsign BH6RIZ-6 and its ACK puts you on that day's roster.

APRSNETCN OA is an APRS message check-in run by APRSNET.CN. It lasts a whole Saturday, Beijing time. OA stands for On Air.

Round #261024 is co-hosted by APRSNETCN and CATHAM 半间猫窝.

One station is on duty each week. Send it a message, it answers with an ACK, and you are on that day's roster. The duty callsign changes every week.

No sign-up, and nothing to be present for.

📡 When, and who is on duty

  • Round #261024, called 半间猫窝 (Half a Cat Bed)
  • Saturday, 24 October 2026, 00:00–23:59 Beijing time (UTC+8)
  • In UTC that is 16:00 on 23 October to 15:59 on 24 October
  • The duty callsign this week is BH6RIZ-6, and zelin is at the key

📮 How to join

Address the message to BH6RIZ-6.

Send CQ CNNET BG7XXX OL62 with your own call and your own grid. When the duty station answers with an ACK, send U CNNET.

You can also send CNNET BG7XXX OL62 and skip the CQ step.

A grid of 4 or 6 characters both work, for example OL62 or OL62AA. If a packet arrives without a grid, the duty station answers with a hint; send it once more with the grid in.

Anything you want to pass on to the duty station goes after the grid. That sentence shows up next to your callsign on the roster.

Packets over the network and packets over RF both count, RF first. An RF packet records the digipeaters it went through.

You need a valid callsign and licence, and please follow your local regulations.

📋 What shows up

The duty station answers every check-in with an ACK.

Your callsign then appears on the activity page roster, with your grid and the time it arrived.

The roster image and the grid image can be downloaded the same day.

🙋 About this round

No scoring, no leaderboard, and no commercial use.

The flow keeps changing; the activity page always carries the current one.

If you miss this one, there is another round next Saturday.

In APRSLocus, open the Messages page and set the recipient to the duty callsign.

The roster for the day is on the activity page. Open the activity page

What It Does

Position tracking, beacon reporting, messaging, group chat — all the APRS essentials, built to be straightforward.

Maps & tracking

01

Real-time Map Tracking

Many tile sources: AMap tiles, AMap satellite, Vector, Carto (light/dark/voyager), OSM (standard/humanitarian), OpenTopo, and Esri. One marker per station (clustering removed in v1.6.149), with trail playback support; the heatmap shows density when zoomed out.

  • GCJ-02 / WGS-84
  • Heatmap
  • Trail Display
02

Immersive Drive View

A navigation-style page built for glancing at while driving: large heading / distance / speed readouts, a nearby-stations panel, and the target station centred.

  • Navigation style
  • Nearby stations
  • Large type
03

Offline Maps

Download the tiles of the current view to the device (resumable, 200k tiles per region) and keep the map with no network at all; a four-step fallback keeps it readable and clickable.

  • Download view
  • Resumable
  • 4-step fallback

Messaging & gateway

04

Position Beacon

One-tap position reporting in standard APRS 1.0 format. Auto-includes altitude, speed, heading, and battery level. Report interval is configurable.

  • Standard Format
  • Auto Attachments
  • Demo Mode
05

Messaging

Private and group chat in a unified conversation list with ACK confirmation. Supports group invites, member management, unread badges, and Chinese text.

  • ACK Confirmation
  • Group Chat
  • Chinese Compatible
06

Two-way Chat Translation

Built-in multi-engine translation that works out of the box on a free endpoint, no API key required. Translate both incoming and outgoing messages, compare against the original, or translate your text into the other station's language before sending.

  • No API key
  • Side-by-side
  • Pre-send
07

Gateway (iGate)

Relays RF packets into APRS-IS, tagging them with qAr / qAR; loop protection is built in (packets already carrying TCPIP* or a q-construct are never echoed back), and the same frame is injected once per 30 seconds. Optional two-way mode sends messages to stations recently heard on RF.

  • RF→IS
  • Loop-safe
  • De-duplication

Stations & data

08

Recognizes station devices via the official aprs.org database (tocalls): vendor + model + device class (rig / HT / tracker / app / gateway…). Filter by status, type, device class or exact model; jump to QRZ callsign DB or aprs.fi for tracks from the details page.

  • Official Device ID
  • Class / Model Filter
  • QRZ / aprs.fi
09

Packet & Log Viewer

Raw packets displayed in monospace with long-press copy. Parsed results sorted by type: position, message, weather, status. Built-in hierarchical logs for debugging.

  • Debug Logs

Internet (APRS-IS), Bluetooth / serial TNC (KISS), sound-card AFSK 1200 (Bell 202 software TNC), Kenwood $PKWDWPL waypoints (receive-only), and WLAN radio direct link (supporting IC-705 / IC-9700 / IC-7610 / IC-905 over Wi-Fi / Ethernet with CI-V and LAN audio). Multiple links can receive simultaneously, while the transmit link is picked separately.

  • APRS-IS
  • TNC

A weather panel whose dynamic background follows the actual conditions, station statistics (latest spot, farthest distance, packet rate), and an honors wall.

v2.0.5 2026-09-27
Fix: 2.0.4's PHG never actually took effect for third parties. In 2.0.4 the data extensions were space-separated (000/000 PHG2130 /A=000033), and the reference implementation (aprslib) reports phg as missing entirely with PHG2130 left as ordinary comment text — meaning third-party maps showed no coverage and the feature did nothing. Two independent traps caused it: (1) APRS101 defines PHG / /A= / CsT as fixed-length data extensions that must be glued to the symbol with no separators (real stations look like …ErPHG1460/A=000071); (2) CsT and PHG compete for the same "start of comment" slot — parsers match ^\d{3}/\d{3} first and, once it hits, only look for a DF report and never search for PHG, so even glued together PHG stays unreadable while 000/000 comes first.
The fix: keep the extension block glued together and give the first slot to PHG — when PHG is present, CsT is no longer sent with the position packet. Afterwards: !2155.17N/11052.40EbPHG2130/A=000033 Bat:22% (spaces appear only between the block and the comment). One trade-off: a mobile station that also fills in PHG shows no speed/bearing on aprs.fi — both need that single "start of comment" slot and cannot coexist; stations without PHG are unaffected. The beacon packet's third-party compatibility test now runs in CI, so this class of "compiles, analyze is green, third parties cannot read it" bug has a guard.

Frequently Asked Questions

From Passcode to battery drain — everything we could think of. The full 23 questions, grouped by topic, live in the Help Center.

Can't receive / send messages?

Most likely an unverified Passcode. Entering -1 only lets you connect — it won't work for messaging. Visit APRS Passcode Generator to generate your own Passcode and enter it in Connection Settings. If the server returns unverified, a yellow banner appears at the top of the home page — tap "Go to Settings" to fix it.

How do I set up a Passcode?

In step 6 of the wizard or under Settings → Connection, use your full callsign (including SSID suffix, e.g. BG7LZQ-3) to generate a Passcode, then paste it in.

Connection fails / keeps dropping?

The app has built-in progressive reconnect (8 → 16 → 32 → 60 seconds). If it persists, check your network and whether the server address and port are blocked, or try a different server in Connection Settings.

Can't see nearby stations on mobile?

Check if your target country/region is selected in the Receive Filter, and verify that the receive range (lat/lon + radius) covers your location. By default, only Chinese (B-prefix) stations are received.

Does background positioning drain the battery?

Android uses a foreground service for continuous positioning. You can adjust the report interval in Location / Beacon settings, or switch to manual reporting to reduce power usage. The notification bar has a one-tap "Exit" button.

Map display issues on Windows?

For best compatibility on Windows, switch to Vector Map (no API key needed) or use Carto / OSM / Esri layers in Display → Map Type.

Signature conflict / version downgrade on install?

Since v1.5.2, Android builds use the official release signature. CI and local builds use the same key — just install over the old version. If upgrading from a much older build, uninstall and reinstall.
