    TNC init string

    Sent line by line after connecting (same as APRSdroid kiss.init)

    ℹ️

    If the TNC receives but will not transmit, try here first: many Bluetooth/serial TNC modules boot into command mode and need KISS ON / RESTART before they will forward in KISS. One command per line (CRLF is appended automatically).

    SettingControlDefaultDescription
    Delay per line (ms) initDelayMsText input300Wait between lines. Modules need time to process commands; too short drops them
    Serial baud rate (bd) serialBaudText input9600A USB serial cable and the radio data port must agree on the speed, otherwise not a single byte gets through. Common values: 9600 / 19200 / 38400 / 57600 / 115200. Bluetooth SPP has no baud rate, so this is ignored for Bluetooth devices.
    Send init string nowButton—
    No init string configuredChoice card—

    KISS parameters

    Link-layer settings pushed straight to the TNC

    SettingControlDefaultDescription
    Push KISS parameters on connect pushKissParamsSwitchoffOff by default (same as APRSdroid). When on, the values above are pushed to the TNC on connect, overriding its own configuration — inappropriate values can make it back off forever without transmitting, so enable only if you want centralised control.
    TX delay (ms) txDelayMsText input300KISS TXDELAY in 10 ms units — time for your PTT to settle before data
    TX tail (ms) txTailMsText input50KISS TXTAIL in 10 ms units — some radios need the tail to be heard fully
    Persistence persistenceText input63KISS PERSISTENCE, 0–255 — lower is more polite and avoids collisions on a shared channel
    Slot time (ms) slotTimeMsText input100KISS SLOTTIME in 10 ms units — works with persistence to pace channel access
    Full duplex fullDuplexSwitchoff
    Channel / KISS port channelText input0Only multi-channel TNCs have several ports; keep 0 for single-channel radios
    Max frame size (bytes) maxFrameText input330Longer packets are not sent at all (at 1200 baud an AX.25 frame is ~330 bytes)
    RF digipeater path pathText inputWIDE1-1,WIDE2-1Digipeaters used on air, e.g. WIDE1-1,WIDE2-1; leave empty for none
    Vendor command hardwareCmdText input-1KISS SETHARDWARE (0x06), vendor-specific; -1 means do not send
    Value hardwareValText input0KISS SETHARDWARE (0x06), vendor-specific; -1 means do not send

    TX self-test

    Writes one test frame to the TNC to tell link problems from TNC problems

    ℹ️

    It sends a status frame (no coordinates), so it will not move your station on aprs.fi. If it reports "written" but nothing is transmitted, the problem is on the TNC side: try the init string (KISS ON / RESTART) first, then check TxDelay and channel occupancy.

    SettingControlDefaultDescription
    Write test frameButton—

    Audio (soundcard TNC)

    Send and receive AFSK 1200 packets with your soundcard

    SettingControlDefaultDescription
    Sample rate sampleRateText input2205022050 Hz is the usual soundcard-TNC rate; use 44100/48000 if unsupported. Changing it restarts capture
    Bit rateText input—APRS on VHF is always 1200 bd (Bell 202); 300 bd is for HF
    Mark tone (Hz)Text input—Bell 202 specifies mark 1200 Hz / space 2200 Hz; the tolerance is only a few Hz
    Space tone (Hz)Text input—Space tone. Together with mark it sets the FSK shift (1000 Hz nominal)
    Tx preamble (ms) txDelayMsText input300Preamble length: lets the far-end demod lock and the radio key up
