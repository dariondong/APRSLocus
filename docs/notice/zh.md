# 📡 2.0.5 已发布 · 修好 2.0.4 的 PHG（第三方读不出）

**2.0.5 已发布。** 这一版修的是 **2.0.4 的一个问题**：填了「功率 / 天线高度 / 增益」之后，报文里的 `PHGphgd` 第三方**读不出来** —— 也就是说 aprs.fi 这类地图上看不到覆盖范围，这个功能等于没做。

如果你装了 **2.0.4**，请升级到 **2.0.5**。

---

## 一、2.0.4 的问题出在哪

2.0.4 发出的报文是这样（注意扩展之间被空格分隔）：

```
BG7LZQ-2>APALOC,TCPIP*,qAC,T2FZ:!2155.17N/11052.40Eb000/000 PHG2130 /A=000033 Bat:22%
```

用参考实现（aprslib）解这条报文，`phg` **完全缺失**、`PHG2130` 被当成普通备注文字。

根因是**两个独立的坑**，只修一个都不够：

1. **数据扩展之间不能有空格**。APRS101 把 PHG、`/A=`、天线的方向速度（CsT）这些定义为**固定长度的数据扩展**，必须紧贴符号、彼此之间不用空格。真实台站都长这样：`!3155.21N/12016.69ErPHG1460/A=000071`。
2. **CsT 与 PHG 争同一个「注释开头」**。解析器先匹配 `ddd/sss` 形式的速度方位角，**一旦匹配上就只再看测向报文，根本不再去找 PHG**。所以哪怕紧贴，只要 `000/000` 排在 PHG 前面，PHG 照样读不出来。

## 二、2.0.5 怎么修的

**扩展块整块紧贴，且把首位让给 PHG** —— 填了 PHG 时，速度/方位角（CsT）不再随位置报文发送。修好后：

```
BG7LZQ-2>APALOC,TCPIP*,qAC,T2FZ:!2155.17N/11052.40EbPHG2130/A=000033 Bat:22%
← 坐标+符号 紧贴 PHG，再紧贴 /A=；空格只出现在扩展块与备注之间
```

**一个取舍要说明**：同时填了 PHG 的**移动台**，aprs.fi 上就没有速度/方位角了 —— 两者都要「注释开头」这一个位置，无法共存。PHG 描述的是固定天线安装，与移动台本不是一类台站。**没填 PHG 的台站一切照旧。**

另外把「信标报文的第三方兼容性」测试纳入了 CI：这类问题编译能过、静态检查也全绿，只有第三方解析器读不出来，只能靠测试守住。

## 三、关于 2.0.3：仍属非正常发行

**2.0.3 仍建议不要使用。** 它源于一次**在正式发版流程之外把版本号从 2.0.2 提升为 2.0.3** 的变更，并据此生成了发行版。

APRSLocus 会把版本号**发送到空中**（APRS-IS 与射频的身份帧 / 在线帧里都带着它）。如果出现两个都自称 **2.0.3** 的安装包，在 aprs.fi 这类平台上就**无法分辨**到底是哪一个在发信标 —— 出了问题也没法定位。因此该版本已从 Release 与官网撤回。

若你安装过 2.0.3，请**升级到 2.0.5**。

## 四、一条规则：版本号只由维护者在发版时提升

功能贡献照常欢迎 —— 提 Issue、报告问题、提交 PR 都可以；需要共同遵守的只有一条：**不要改动版本号**，它只在正式发版时由维护者统一提升。
