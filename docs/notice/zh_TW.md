# 📡 2.0.5 已發布 · 修好 2.0.4 的 PHG（第三方讀不出）

**2.0.5 已發布。** 這一版修的是 **2.0.4 的一個問題**：填了「功率 / 天線高度 / 增益」之後，報文裡的 `PHGphgd` 第三方**讀不出來** —— 也就是說 aprs.fi 這類地圖上看不到涵蓋範圍，這個功能等於沒做。

如果你裝了 **2.0.4**，請升級到 **2.0.5**。

---

## 一、2.0.4 的問題出在哪

2.0.4 送出的報文是這樣（注意擴充之間被空格分隔）：

```
BG7LZQ-2>APALOC,TCPIP*,qAC,T2FZ:!2155.17N/11052.40Eb000/000 PHG2130 /A=000033 Bat:22%
```

用參考實作（aprslib）解這條報文，`phg` **完全缺失**、`PHG2130` 被當成普通備註文字。

根因是**兩個獨立的坑**，只修一個都不夠：

1. **資料擴充之間不能有空格**。APRS101 把 PHG、`/A=`、天線的方向速度（CsT）這些定義為**固定長度的資料擴充**，必須緊貼符號、彼此之間不用空格。真實臺站都長這樣：`!3155.21N/12016.69ErPHG1460/A=000071`。
2. **CsT 與 PHG 爭同一個「註解開頭」**。解析器先匹配 `ddd/sss` 形式的速度方位角，**一旦匹配上就只再看測向報文，根本不再去找 PHG**。所以哪怕緊貼，只要 `000/000` 排在 PHG 前面，PHG 照樣讀不出來。

## 二、2.0.5 怎麼修的

**擴充區塊整塊緊貼，且把首位讓給 PHG** —— 填了 PHG 時，速度/方位角（CsT）不再隨位置報文發送。修好後：

```
BG7LZQ-2>APALOC,TCPIP*,qAC,T2FZ:!2155.17N/11052.40EbPHG2130/A=000033 Bat:22%
← 座標+符號 緊貼 PHG，再緊貼 /A=；空格只出現在擴充區塊與備註之間
```

**一個取捨要說明**：同時填了 PHG 的**移動臺**，aprs.fi 上就沒有速度/方位角了 —— 兩者都要「註解開頭」這一個位置，無法共存。PHG 描述的是固定天線安裝，與移動臺本不是一類臺站。**沒填 PHG 的臺站一切照舊。**

另外把「信標報文的第三方相容性」測試納入了 CI：這類問題編譯能過、靜態檢查也全綠，只有第三方解析器讀不出來，只能靠測試把關。

## 三、關於 2.0.3：仍屬非正常發行

**2.0.3 仍建議不要使用。** 它源於一次**在正式發版流程之外把版本號從 2.0.2 提升為 2.0.3** 的變更，並據此生成了發行版。

APRSLocus 會把版本號**發送到空中**（APRS-IS 與射頻的身分幀 / 在線幀裡都帶著它）。如果出現兩個都自稱 **2.0.3** 的安裝包，在 aprs.fi 這類平台上就**無法分辨**到底是哪一個在發信標 —— 出了問題也沒法定位。因此該版本已從 Release 與官網撤回。

若你安裝過 2.0.3，請**升級到 2.0.5**。

---

## 四、一條規則：版本號只由維護者在發版時提升

功能貢獻照常歡迎 —— 提 Issue、回報問題、提交 PR 都可以；需要共同遵守的只有一條：**不要改動版本號**，它只在正式發版時由維護者統一提升。
